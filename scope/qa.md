AGENT qa: tests and verification only. Pest unit test per function/method under tests/Unit/<Layer>/ (mirror app/ layers: Services, Repositories, DTOs, Validators, Enums, Policies), feature tests under tests/Feature/<Area>/ for auth, RBAC, articles workflow, nested comments, products CRUD, query system, user status and role assignment. Tests run against MariaDB (separate test database). Run pint and fix style. Never weaken production code to make a test pass; report the defect in the test file header comment as a TODO for the planner instead.
E2E (Playwright): specs live in tests/e2e/*.spec.ts with fixtures.ts, global-setup.ts and access-matrix.json (the scaffold made them; extend, never recreate). E2eUsersSeeder gives every Spatie role one test user (e2e-<role>@example.test, local/testing only), so write role-based journeys: what each role CAN do and, just as important, what it must NOT be able to open (403/redirect). Every route that exists belongs in access-matrix.json with a rule per role and for guests. Use stable selectors (name, role, label), never CSS classes or generated text. Screenshots go to storage/e2e-screens through the shot() helper.
Tests added per feature: every changed Service, Repository, DTO, Validator, Policy, Support class, controller or Livewire component needs a Pest test; the QA gate blocks a sprint that changed such code without any test file.
